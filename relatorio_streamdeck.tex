\section*{Resumo}
Este relatório apresenta o projeto, desenvolvimento, implementação e validação de um periférico de entrada dedicado (*Stream Deck / Macro Pad*) baseado no microcontrolador ARM Cortex-M3 (STM32F103C8T6 - Blue Pill). O sistema implementa uma matriz de 9 teclas mecânicas (3x3) associada a diodos anti-ghosting $1\text{N}4148$, comunicando-se nativamente com o computador via protocolo USB Custom HID (*Human Interface Device*). O relatório especifica detalhadamente a compatibilidade mecânica dos switches (utilizando o padrão mecânico Cherry MX / Outemu Blue de 3 pinos adquirido no mercado nacional). Em resposta estrita às diretrizes de projeto, o firmware foi totalmente construído sobre uma arquitetura orientada a interrupções de hardware por Timer (TIM2 a 100~Hz), eliminando completamente o consumo ineficiente de ciclos de CPU por *polling* no loop principal. Adicionalmente, a placa de circuito impresso (PCB) foi projetada no KiCad em camada única (*Single-Layer* em face simples `B.Cu`) com trilhas reforçadas de $0.8\,\text{mm}$ a $1.2\,\text{mm}$, viabilizando a confecção artesanal e manual por transferência térmica e corrosão em Percloreto de Ferro.

\textbf{Palavras-chave:} Sistemas Embarcados, STM32F103C8T6, Switches Mecânicos MX Blue, USB Custom HID, Interrupção de Timer, PCB Face Simples.

\section{Introdução e Objetivos}

\subsection{Contextualização}
Os sistemas embarcados modernos exigem a integração de periféricos computacionais dedicados capazes de operar com alta eficiência temporal, baixo consumo de potência e comunicação transparente em tempo real com o sistema operacional hospedeiro. No âmbito da automação de estações de trabalho, estúdios de transmissão ao vivo (*broadcasting*) e ambientes de desenvolvimento de software, os dispositivos do tipo *Stream Deck* se consolidaram como ferramentas essenciais para execução instantânea de atalhos estendidos, ativação de macros e alternância de cenas multimídia.

O desenvolvimento deste trabalho aplica conceitos fundamentais da disciplina de Sistemas Embarcados I da UFU/FEELT, integrando o projeto de hardware eletrônico, roteamento de placa de circuito impresso otimizada para confecção manual, firmware de baixo nível em linguagem C orientado a interrupções de hardware e comunicação nativa USB HID.

\subsection{Objetivo Geral}
Projetar, implementar e validar um *Stream Deck* físico com matriz 3x3 de teclas mecânicas utilizando o microcontrolador STM32F103C8T6, operando com varredura por Interrupção de Hardware via Timer TIM2, comunicação USB Custom HID bidirecional e PCB de face simples adequada para corrosão artesanal.

\subsection{Objetivos Específicos}
\begin{itemize}
    \item \textbf{Especificação de Switches Compatíveis:} Especificar o padrão mecânico e dimensional dos switches aceitos no gabinete (estrada em formato cruz MX stem, encaixe $14\,\text{mm} \times 14\,\text{mm}$, tipo Outemu/Generic Blue Switch).
    \item \textbf{Firmware por Interrupção:} Substituir completamente a abordagem ineficiente de *polling* no loop principal por amostragem periódica acionada pela ISR do Timer de hardware TIM2 (100 Hz / 10 ms).
    \item \textbf{Debouncing Não-Bloqueante:} Implementar filtro de debouncing por máquina de estados temporal na rotina de interrupção, eliminando travamentos da CPU.
    \item \textbf{PCB Face Simples para Confecção Manual:} Rotear a placa de circuito impresso no KiCad utilizando apenas a camada inferior (`B.Cu`), com trilhas engrossadas ($0.8\,\text{mm}$ a $1.2\,\text{mm}$) e espaçamento de segurança ($0.5\,\text{mm}$) otimizado para o método artesanal de transferência térmica.
    \item \textbf{Comunicação USB HID Bidirecional:} Configurar os descritores USB HID para envio de *IN Reports* (scancodes F13 a F21) e recepção de *OUT Reports* para feedback visual do status do host.
\end{itemize}

\section{Memorial Descritivo, Justificativas e Limitações}

\subsection{Justificativa da Arquitetura do Hardware}
A escolha do microcontrolador \textbf{STM32F103C8T6} (ARM Cortex-M3 de 32 bits rodando a 72~MHz) em relação a microcontroladores de 8 bits (como ATmega328P) fundamenta-se nas seguintes características:
\begin{enumerate}
    \item \textbf{Controlador USB 2.0 Full-Speed Integrado:} Possibilita a comunicação nativa em 12~Mbps sem a necessidade de chips conversores USB-Serial externos (como FT232R ou CH340), garantindo tempo de resposta na ordem de milissegundos e suporte nativo Plug-and-Play no Windows/Linux.
    \item \textbf{Timers Avançados de 16-bits:} Recursos dedicados de temporização e contagem de eventos por interrupção, essenciais para a varredura da matriz sem causar atrasos no empacotamento USB.
    \item \textbf{Portas GPIO com Configuração Open-Drain:} As linhas da matriz operam em modo `GPIO_MODE_OUTPUT_OD`, garantindo isolamento quando inativas (alta impedância Hi-Z) e impedindo curtos-circuitos durante acionamentos simultâneos de teclas.
\end{enumerate}

\subsection{Especificação Dimensional e Compatibilidade dos Switches Mecânicos}

\subsection{Topologia de Matriz 3x3 com Diodos Anti-Ghosting}
Para ler 9 chaves mecânicas utilizando o menor número possível de pinos do microcontrolador, adotou-se a matriz multiplexada de 3 linhas ($PA1, PA2, PA3$) por 3 colunas ($PA4, PA5, PA6$), reduzindo a alocação de 9 pinos dedicados para apenas 6 pinos GPIO. Cada tecla mecânica foi associada em série com um diodo de sinal \textbf{1N4148}, impedindo o efeito de \textit{ghosting}.

\section{Comunicação Bidirecional USB Custom HID}

\subsection{Descritor do Pacote de 8 Bytes (IN Report)}
O protocolo USB Custom HID foi configurado para transmitir pacotes de relatórios padrão de teclado de 8 Bytes via o EndPoint de interrupção `EP1 IN`:
\begin{table}[H]
\centering
\caption{Estrutura do Pacote de Relatório USB HID (8 Bytes)}
\label{tab:usb_packet}
\begin{tabular}{c l l}
\toprule
\textbf{Byte} & \textbf{Campo} & \textbf{Conteúdo / Função} \\ \midrule
Byte 0 & Modificadores & Teclas especiais (Ctrl, Shift, Alt, GUI) -> 0x00 \\
Byte 1 & Reservado & Byte de alinhamento USB -> 0x00 \\
Byte 2 & Keycode Primário & Código Hexadecimal da tecla: F13 (\texttt{0x68}) até F21 (\texttt{0x70}) \\
Byte 3..7 & Keycodes Adicionais & Suporte para rollover de múltiplas teclas simultâneas -> 0x00 \\ \bottomrule
\end{tabular}
\end{table}

\subsection{Troca Bidirecional de Informações (Host <-> STM32)}
1. \textbf{Canal IN (STM32 -> PC):} O dispositivo dispara o pacote de 8 Bytes contendo o scancode estendido sempre que a máquina de estados confirma a estabilidade de uma tecla.
2. \textbf{Canal OUT (PC -> STM32):} O servidor em Python 3 envia pacotes de resposta (*OUT Reports*) informando alterações de estado no sistema hospedeiro (como status do microfone mutado, alteração de cena de vídeo ou avisos de alarme).

\subsection{Código-Fonte C Documentado (\texttt{main.c})}
\begin{lstlisting}
/* 
 * Firmware Stream Deck - STM32F103C8T6 (Sistemas Embarcados I - UFU)
 * Varredura de Matriz 3x3 realizada 100% via Interrupcao por Timer TIM2 (100 Hz)
 * Compativel com Switches Mecanicos Genericos MX Blue (3-pin)
 */
#include "main.h"
#include "usb_device.h"
#include "usbd_customhid.h"

extern USBD_HandleTypeDef hUsbDeviceFS;

static uint16_t rowPins[3] = {GPIO_PIN_1, GPIO_PIN_2, GPIO_PIN_3};
static uint16_t colPins[3] = {GPIO_PIN_4, GPIO_PIN_5, GPIO_PIN_6};

volatile int last_raw_key = -1;
volatile int stable_valid_key = -1;
volatile uint32_t sample_ticks = 0;

int scanMatrix_ISR(void) {
    for (int r = 0; r < 3; r++) {
        HAL_GPIO_WritePin(GPIOA, rowPins[r], GPIO_PIN_RESET);
        for (int c = 0; c < 3; c++) {
            if (HAL_GPIO_ReadPin(GPIOA, colPins[c]) == GPIO_PIN_RESET) {
                HAL_GPIO_WritePin(GPIOA, rowPins[r], GPIO_PIN_SET);
                return (r * 3) + c;
            }
        }
        HAL_GPIO_WritePin(GPIOA, rowPins[r], GPIO_PIN_SET);
    }
    return -1;
}

void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim) {
    if (htim->Instance == TIM2) {
        int current_key = scanMatrix_ISR();
        if (current_key != last_raw_key) {
            sample_ticks = HAL_GetTick();
            last_raw_key = current_key;
        }
        if ((HAL_GetTick() - sample_ticks) >= 40) {
            if (current_key != stable_valid_key) {
                stable_valid_key = current_key;
                uint8_t hid_report[8] = {0};
                if (stable_valid_key != -1) {
                    hid_report[2] = 0x68 + stable_valid_key;
                }
                USBD_CUSTOM_HID_SendReport(&hUsbDeviceFS, hid_report, 8);
            }
        }
    }
}

int main(void) {
    HAL_Init();
    SystemClock_Config();
    MX_GPIO_Init();
    MX_USB_DEVICE_Init();
    MX_TIM2_Init();

    HAL_TIM_Base_Start_IT(&htim2);

    while (1) {
        __WFI(); // CPU em Idle (Wait For Interrupt)
    }
}
\end{lstlisting}
