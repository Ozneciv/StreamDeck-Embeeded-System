\section*{Resumo}
\hspace*{1.25cm}Este relatório apresenta o desenvolvimento, implementação e validação de um periférico de entrada dedicado (\textit{Stream Deck / Macro Pad}) baseado no microcontrolador ARM Cortex-M3 (STM32F103C8T6 - Blue Pill). O dispositivo é composto por uma matriz 3x3 de teclas mecânicas acopladas a diodos anti-ghosting $1\text{N}4148$, operando nativamente como protocolo USB Custom HID (\textit{Human Interface Device}). O relatório especifica a compatibilidade mecânica dos switches (utilizando o padrão mecânico Cherry MX / Outemu Blue de 3 pinos adquirido no mercado nacional). Em estrito atendimento às recomendações da banca, a arquitetura do firmware foi totalmente reformulada para operar \textbf{100\% sob Interrupção de Hardware por Timer (TIM2 a 100~Hz / 10~ms)} com filtro de debouncing por máquina de estados, desativação de \textit{polling} no loop principal via instrução \texttt{\_\_WFI()}, re-enumeração USB automática por software em \texttt{PA12}, otimizaciones no tamanho dos Endpoints de relatório USB HID para 8 Bytes e suporte à depuração ST-LINK em baixa potência (\texttt{DBGMCU}). Adicionalmente, a placa de circuito impresso (PCB) foi projetada no KiCad em \textbf{camada única (Face Simples \texttt{B.Cu})} com trilhas engrossadas de $0.8\,\text{mm}$ a $1.2\,\text{mm}$, viabilizando a corrosão artesanal manual com Percloreto de Ferro.

\textbf{Palavras-chave:} Sistemas Embarcados, STM32F103C8T6, USB Custom HID, Interrupção por Timer (TIM2), Re-enumeração USB, PCB Face Simples.

\section{Introdução}
\hspace*{1.25cm}Os sistemas embarcados estão presentes em diversas aplicações tecnológicas, desempenhando funções específicas por meio da integração entre hardware e software. Esses sistemas são amplamente utilizados em dispositivos eletrônicos que exigem processamento dedicado, baixo consumo de energia e interação eficiente com o usuário, tornando-se fundamentais em áreas como automação, controle e interfaces inteligentes.

Neste contexto, o desenvolvimento de um \textit{Stream Deck} representa uma aplicação prática dos conceitos estudados na disciplina de Sistemas Embarcados I da UFU/FEELT. O dispositivo consiste em um controlador com teclas programáveis, capaz de executar comandos previamente configurados, como abertura de programas, envio de atalhos de teclado (F13 a F21), controle de aplicações e automação de tarefas. Essa tecnologia é amplamente empregada por criadores de conteúdo, profissionais de transmissão ao vivo, designers e programadores.

O projeto proporcionou a aplicação de conhecimentos relacionados à programação de microcontroladores, integração de periféricos, comunicação entre dispositivos e desenvolvimento de interfaces de interação. Além disso, possibilitou compreender as etapas envolvidas na concepção, implementação e validação de um sistema embarcado funcional, reforçando a relação entre os conceitos teóricos abordados em sala de aula e sua aplicação prática.

\section{Objetivos}

\subsection{Objetivo Geral}
\hspace*{1.25cm}Desenvolver um Stream Deck utilizando conceitos de sistemas embarcados, integrando hardware e software para criar um dispositivo capaz de executar comandos e automatizar tarefas por meio de teclas programáveis.

\subsection{Objetivos Específicos}

    \item Implementar a programação do microcontrolador por meio de \textbf{Interrupção de Timer de Hardware (TIM2 a 100~Hz)}, eliminando o \textit{polling} no loop principal via instrução \texttt{\_\_WFI()}.
    \item Implementar a re-enumeração USB automática por software na inicialização (pino \texttt{PA12}) para forçar a identificação limpa no sistema operacional.
    \item Corrigir os limites de memória da biblioteca ST USB Custom HID, ajustando o tamanho do relatório (\texttt{USBD\_CUSTOM\_HID\_REPORT\_DESC\_SIZE = 63}) e dos Endpoints IN/OUT (\texttt{CUSTOM\_HID\_EPIN\_SIZE = 8}).
    \item Especificar a compatibilidade mecânica dos switches (padrão Cherry MX / Outemu Blue de 3 pinos com encaixe $14\,\text{mm} \times 14\,\text{mm}$).
    \item Desenvolver a PCB no KiCad em \textbf{Face Simples (Single Layer \texttt{B.Cu})} com trilhas engrossadas ($0.8\,\text{mm}$ a $1.2\,\text{mm}$) para corrosão manual.
    \item Habilitar o suporte de depuração SWD em modo Sleep via \texttt{HAL\_DBGMCU\_EnableDBGSleepMode()}.
    \item Consolidar a montagem física com carcaça impressa em 3D, insertos roscados M3 e parafusos M3x8mm.
\end{itemize}

\section{Fundamentação Teórica}
\hspace*{1.25cm}Os sistemas embarcados são sistemas computacionais dedicados ao desempenho de funções específicas, integrando hardware e software em um único dispositivo. Diferentemente dos computadores de uso geral, esses sistemas são projetados para executar tarefas determinadas com alta eficiência, confiabilidade e baixo consumo de recursos.

O funcionamento do Stream Deck baseia-se na leitura do estado das teclas por um microcontrolador, que interpreta cada acionamento e envia o comando correspondente ao computador. Para garantir o correto funcionamento do teclado, utiliza-se uma matriz de teclas associada a diodos $1\text{N}4148$, evitando o fenômeno conhecido como \textit{ghosting}, que pode provocar o reconhecimento incorreto de múltiplas teclas pressionadas simultaneamente.

Outro aspecto importante do projeto é a integração entre os componentes mecânicos e eletrônicos. Os switches mecânicos (especificados no padrão Cherry MX / Outemu Blue com encaixe $14\,\text{mm} \times 14\,\text{mm}$ e força de atuação de $60\,\text{g}$) proporcionam maior precisão e durabilidade em relação aos botões convencionais. A estrutura física do dispositivo é produzida por manufatura aditiva (impressão 3D), permitindo a fabricação de uma carcaça personalizada, de baixo custo e adequada às dimensões do circuito eletrônico.

\subsection{Configuração do Timer TIM2 e NVIC no STM32CubeMX}
\hspace*{1.25cm}Após a definição do circuito eletrônico, realizou-se a configuração do timer de hardware \textbf{TIM2} e do controlador de interrupções (NVIC) no STM32CubeMX:
\begin{itemize}
    \item \textbf{Clock de Entrada do Timer (APB1 Timer Clock):} $72\,\text{MHz}$.
    \item \textbf{Prescaler (PSC):} $7199$. A frequência de contagem do timer resulta em:
    \begin{equation}
        f_{\text{tick}} = \frac{72.000.000\,\text{Hz}}{7199 + 1} = 10.000\,\text{Hz} \implies T_{\text{tick}} = 0,1\,\text{ms}
    \end{equation}
    \item \textbf{Counter Period (ARR):} $99$. O período de interrupção da ISR é dado por:
    \begin{equation}
        T_{\text{ISR}} = (99 + 1) \times 0,1\,\text{ms} = 10\,\text{ms} \implies f_{\text{ISR}} = 100\,\text{Hz}
    \end{equation}
    \item \textbf{Vetor de Interrupção NVIC:} Habilitada a interrupção \texttt{TIM2\_IRQn} com prioridade 0, gerando a rotina \texttt{TIM2\_IRQHandler()} no arquivo \texttt{stm32f1xx\_it.c}.
\end{itemize}

As portas GPIO foram alocadas da seguinte forma:
\begin{itemize}
    \item \textbf{Linhas (\texttt{LINE\_1} a \texttt{LINE\_3}):} Pinos \texttt{PA1}, \texttt{PA2}, \texttt{PA3} em \texttt{GPIO\_MODE\_OUTPUT\_OD} (Open Drain).
    \item \textbf{Colunas (\texttt{COL\_1} a \texttt{COL\_3}):} Pinos \texttt{PA4}, \texttt{PA5}, \texttt{PA6} em \texttt{GPIO\_MODE\_INPUT} com \texttt{GPIO\_PULLUP} interno.
    \item \textbf{Comunicação USB HID:} Pinos \texttt{PA11} (\texttt{USB\_DM}) e \texttt{PA12} (\texttt{USB\_DP}) na classe Custom HID.
    \item \textbf{Interface SWD Debugger:} Pinos \texttt{PA13} (\texttt{SYS\_JTMS-SWDIO}) e \texttt{PA14} (\texttt{SYS\_JTCK-SWCLK}).
\end{itemize}

\subsection{Otimizações Avançadas de Firmware e Pilha USB}
\hspace*{1.25cm}Durante os testes práticos com o protótipo montado, foram implementadas quatro otimizações fundamentais de engenharia no firmware:

\begin{enumerate}
    \item \textbf{Re-enumeração USB D+ por Software:} Como as placas BluePill não possuem circuito transistorizado na linha \texttt{USB\_DP} (\texttt{PA12}), adicionou-se um pulso de desconexão forçada por software em \texttt{main.c} antes de iniciar a pilha USB. O pino \texttt{PA12} é forçado a nível baixo ($0\,\text{V}$) por $100\,\text{ms}$, fazendo com que o sistema operacional hospedeiro invalide a sessão antiga e re-enumere o dispositivo de forma automática imediatamente após a gravação via ST-LINK.
    \item \textbf{Correção nos Endpoints USB Custom HID:} Corrigiu-se o tamanho de memória dos buffers de transferência. O tamanho do relatório (\texttt{USBD\_CUSTOM\_HID\_REPORT\_DESC\_SIZE}) foi atualizado de 2 para 63 bytes em \texttt{usbd\_conf.h} e \texttt{.ioc}, eliminando 61 avisos de compilação (\textit{excess elements in array initializer}). Adicionalmente, o tamanho dos Endpoints de transferência (\texttt{CUSTOM\_HID\_EPIN\_SIZE} e \texttt{CUSTOM\_HID\_EPOUT\_SIZE}) foi expandido para 8 Bytes (\texttt{0x08U}), garantindo o envio completo do pacote de relatório de teclado padrão.
    \item \textbf{Suporte à Depuração ST-LINK em Modo Sleep:} Ao colocar a CPU em repouso com \texttt{\_\_WFI()}, o relógio do gravador SWD era interrompido. A inclusão da função \texttt{HAL\_DBGMCU\_EnableDBGSleepMode()} no ciclo de inicialização permitiu manter a depuração em tempo real ativa no STM32CubeIDE mesmo com a CPU em baixo consumo.
    \item \textbf{Micro-delay de Estabilização Elétrica na Matriz:} Na função \texttt{scanMatrix\_ISR()}, foi introduzido um pequeno atraso de 50 ciclos \texttt{\_\_NOP()}, evitando falsos acionamentos por capacitância parasita acumulada nas trilhas da PCB artesanal.
\end{enumerate}

\subsection{Varredura da Matriz por Interrupção de Timer (TIM2)}
\hspace*{1.25cm}Para atender integralmente à exigência de eliminar o \textit{polling} no \texttt{while(1)}, o timer de hardware \textbf{TIM2} dispara a interrupção periódica a cada 10 ms (100 Hz), executando a callback \texttt{HAL\_TIM\_PeriodElapsedCallback()} que realiza a amostragem e a máquina de estados de debouncing de 40 ms. O loop principal permanece 100\% ocioso em \texttt{\_\_WFI()}.

\subsection{Código-Fonte C Documentado (\texttt{main.c})}
\begin{lstlisting}
/* 
 * Firmware Stream Deck - STM32F103C8T6 (Sistemas Embarcados I - UFU)
 * Arquitetura por Interrupcao de Timer TIM2 (100 Hz), Re-enumeracao USB e Low-Power
 */
#include "main.h"
#include "usb_device.h"
#include "usbd_customhid.h"

extern USBD_HandleTypeDef hUsbDeviceFS;

static uint16_t rowPins[3] = {GPIO_PIN_1, GPIO_PIN_2, GPIO_PIN_3};
static uint16_t colPins[3] = {GPIO_PIN_4, GPIO_PIN_5, GPIO_PIN_6};
static GPIO_TypeDef* rowPorts[3] = {GPIOA, GPIOA, GPIOA};
static GPIO_TypeDef* colPorts[3] = {GPIOA, GPIOA, GPIOA};

volatile int last_raw_key = -1;
volatile int stable_valid_key = -1;
volatile uint32_t sample_ticks = 0;

/* Varredura com micro-delay capacitivo executada em contexto de ISR */
int scanMatrix_ISR(void) {
    for (int r = 0; r < 3; r++) {
        HAL_GPIO_WritePin(rowPorts[r], rowPins[r], GPIO_PIN_RESET);
        for (volatile int i = 0; i < 50; i++) { __NOP(); } // Descarga parasita
        for (int c = 0; c < 3; c++) {
            if (HAL_GPIO_ReadPin(colPorts[c], colPins[c]) == GPIO_PIN_RESET) {
                HAL_GPIO_WritePin(rowPorts[r], rowPins[r], GPIO_PIN_SET);
                return (r * 3) + c;
            }
        }
        HAL_GPIO_WritePin(rowPorts[r], rowPins[r], GPIO_PIN_SET);
    }
    return -1;
}

/* Callback de Interrupcao do Timer TIM2 (100 Hz / 10ms) */
void HAL_TIM_PeriodElapsedCallback(TIM_HandleTypeDef *htim) {
    if (htim->Instance == TIM2) {
        int current_key = scanMatrix_ISR();
        if (current_key != last_raw_key) {
            sample_ticks = HAL_GetTick();
            last_raw_key = current_key;
        }
        if ((HAL_GetTick() - sample_ticks) >= 40) {
            if (current_key != stable_valid_key) {
                stable_valid_key = current_key;
                uint8_t hid_report[8] = {0};
                if (stable_valid_key != -1) {
                    hid_report[2] = 0x68 + stable_valid_key; // F13 a F21
                }
                USBD_CUSTOM_HID_SendReport(&hUsbDeviceFS, hid_report, 8);
            }
        }
    }
}

\section{Conclusão}
\hspace*{1.25cm}O desenvolvimento do Stream Deck customizado demonstrou-se totalmente viável na integração entre a arquitetura de hardware e o projeto mecânico. A utilização do microcontrolador STM32F103C8T6 (Blue Pill), configurado via STM32CubeMX e programado com \textbf{Interrupção de Timer de Hardware (TIM2 a 100 Hz)} para operar como um dispositivo USB HID com clock ajustado em 48 MHz, assegurou a comunicação nativa e o disparo imediato de atalhos e macros no computador sem o uso de \textit{polling}. A organização da leitura dos botões em uma matriz 3x3 com diodos anti-ghosting 1N4148 otimizou a alocação dos pinos do chip. A PCB projetada em \textbf{face simples (\texttt{B.Cu}) com trilhas reforçadas de $0.8\,\text{mm}$ a $1.2\,\text{mm}$} viabilizou a confecção artesanal. Dessa forma, o projeto valida a aplicação prática de sistemas embarcados e prototipagem física na criação de um periférico funcional, preciso e sob medida.
